第 06 章　数据库与 SQL 注入：数据变成语法的瞬间

先花十分钟学会读一张表，再理解「拼接」为什么必然出事，最后按回显形态分成四种注入打法。

本章你会得到

  • 数据库最小概念：表、行、列、主键、查询
  • 看懂一条 SELECT，并能说出它"被拼接"时哪里会断
  • 四种注入形态（联合/报错/布尔盲/时间盲）的判断方法与对应 payload 形态
  • 知道为什么"没回显"也能注入

数据库在解决什么问题

网站要存"用户、文章、订单"。用文本文件存会立刻崩溃：多人同时写、查一条要遍历整个文件、改一半断电就坏。 数据库解决的就是这三件事：并发、查询、事务（要么全成要么全不成）。

概念比喻一句话
表（table）一张 Excel同一类东西放一起：users / news / orders
行（row）Excel 的一行一条记录：某个用户
列（column）Excel 的一列一个字段：username / password / is_admin
主键（primary key）身份证号唯一标识一行，通常叫 id
查询（query）筛选取数SELECT 列 FROM 表 WHERE 条件
SELECT id, username FROM users WHERE username = 'admin';

漏洞的根：字符串拼接

为什么这个洞几十年都杀不完

因为"拼字符串"是最符合直觉的写法：你要查什么，就把条件写进句子。 SQL 是一门语言，而语言里"引号内的内容"是数据、"引号外"才是语法。 只要用户输入能带一个引号进来，他就能提前结束"数据区"，把自己后面的内容变成语法。

参数化查询（prepared statement）之所以治本，是因为它先把语法结构定死， 再把用户值当"纯数据"塞进去 —— 用户写什么都不会改变句式。

四种形态：按"服务器怎么回答你"分类

形态服务器会告诉你什么你怎么取数据判断方法
联合注入
UNION		把查询结果直接显示在页面上 用 UNION SELECT 把想要的数据"并"到结果里 先试 ' 看报错；再用 order by N 探列数
报错注入只回显数据库报错 把数据塞进报错信息（updatexml/extractvalue/floor） 页面出现 SQL 报错关键字
布尔盲注只回"有结果/没结果"两种页面 一个字一个字问"第 1 个字符是不是 'f'" and 1=1 与 and 1=2 页面不同
时间盲注连"有没有结果"都看不出来 用 sleep(3) 让响应变慢，用时间当信号 and sleep(3) 响应变慢约 3 秒
先判断形态，再选 payload（顺序反了就白打）
  1. 发 id=1'：看到数据库报错吗？→ 有报错，试报错注入或联合
  2. 发 and 1=1 / and 1=2：两次页面长度差得多吗？→ 布尔盲
  3. 发 and sleep(3)：明显慢了吗？→ 时间盲
  4. 三步都不动 → 可能没注入，或者被 WAF 挡了（看第 5 章的编码绕过）

联合注入的最小流程（题型 90% 是它）

① 探列数：  ?id=1 order by 3 -- -      → 报错说明列数 < 3
            ?id=1 order by 2 -- -      → 正常，说明 2 列
② 找回显位：?id=1 and 1=2 union select 1,2 -- -
            → 页面上出现 "2" 的位置就是第 2 列会回显
③ 取数据：  ?id=1 and 1=2 union select 1,database() -- -
            ?id=1 and 1=2 union select 1,group_concat(table_name)
                 from information_schema.tables where table_schema=database() -- -
④ 取列名 → 取字段 → 拿到 flag
为什么要 and 1=2，为什么结尾要 -- -

and 1=2 让原来的查询查不到东西，页面就只剩你 union 出来的那行 —— 否则你自己的数据会被原结果淹没。

-- - 是注释：把原句剩下的部分（比如 ' LIMIT 1）注释掉，否则语法会断。 MySQL 里注释也可写成 #，但 -- 后面必须跟空格（所以常见写法是 -- - 或 --+）。

盲注：没有回显时怎么"读"数据

假设只能判断真假，可以把数据变成"是非题"：

?id=1 and substr((select flag from flag),1,1)='f'   → 页面正常 = 猜对
?id=1 and ascii(substr((select flag from flag),1,1))>100   → 二分法加速
?id=1 and if(substr((select flag from flag),1,1)='f',sleep(3),0)  → 时间盲
盲注的现实代价

一个字符要问 1~7 次，flag 长 30 字符就要两百多个请求。所以工具会做"二分 + 并发 + 提前停止"， 手打的话建议直接用工具里的 sqli_blind 策略或「SQL 注入台」面板。 这也是"为什么要有工具箱"的最好例子：把机械劳动交给程序。

常见过滤与绕法（只需记住四类）

过滤绕法为什么有效
空格被拦/**/、%09、()SQL 里注释和制表符都算空白

工具箱里对应什么

「SQL 注入台」面板：填 URL 和参数，自动探列数/回显位、拖库。 「洪水」里 sqli_union（联合）、sqli_blind（盲注）、 sql_error（报错）、sqli_stack（堆叠）、sqli_waf（绕 WAF）、 login_inject（登录框）、second_order（二次注入）。 它们共用一条判据：只认数据库里取出来的那个 flag，页面 200 不算。
