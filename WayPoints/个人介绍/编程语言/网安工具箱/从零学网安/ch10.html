第 10 章　信息收集：把「一个网址」变成「一张清单」

真实比赛里，第一步永远不是打 payload，而是搞清楚对面是什么。这一章给出按顺序做的四步，以及每一步在找什么。

本章你会得到

  • 四步信息收集流程，以及每一步"看什么信号"
  • 常见泄露文件清单（为什么它们会存在）
  • 指纹识别：从响应头和报错看出技术栈

第 0 步：先看"它想让你干什么"

打开首页，记三件事：有没有登录框、有没有输入框、有没有文件上传。 这三样直接决定你该走哪条线：

看到大概率是先试什么
登录框弱口令 / 登录注入 / 认证绕过admin/admin、admin' -- -
搜索/查询参数SQL 注入 / SSTI / 命令注入引号、{{7*7}}、;id
文件上传上传绕过 / 竞争 / 包含配合先传个 txt 看落点
"读取文件"输入框任意文件读取 / 包含/etc/passwd、../
只显示 id 的页面越权 / 盲注改 id、and 1=1
为什么这一步就能省掉一半时间

因为每类功能能出的洞是有限的。反过来，如果你不管三七二十一把所有 payload 都打一遍， 不但慢，而且容易触发 WAF 把 IP 封了 —— 比赛里这就等于提前结束。

第 1 步：技术栈指纹（它是什么写的）

信号说明怎么利用
Server: nginx/1.20.1服务器软件与版本查该版本已知漏洞 / 解析特性
X-Powered-By: PHP/7.3.29后端语言决定 payload 语法与可用函数
Cookie 名字PHPSESSID=PHP、JSESSIONID=Java、connect.sid=Node直接知道后端
报错页样式ThinkPHP / Spring / Laravel 各有特征查框架已知 RCE
URL 后缀.php / .jsp / .do / 无后缀猜路由与入口
curl -I http://TARGET/           # 只看响应头，最快
curl -s http://TARGET/robots.txt # 作者常在这里留路径
curl -s http://TARGET/.git/HEAD  # 顺手试一下源码泄露

第 2 步：找"本来不该公开"的文件

文件为什么它会存在泄露什么
.git/开发时 git 初始化过，部署时忘了删全部源码与历史提交（可能含密码）
.svn/、.DS_Store版本控制/ macOS 打包残留文件清单（知道有哪些隐藏文件）
www.zip、backup.tar.gz、index.php.bak运维备份习惯源码
.env存数据库密码/密钥数据库口令、JWT 密钥
phpinfo.php调试用绝对路径、扩展、disable_functions
/actuator/env、/swagger-ui.htmlSpring 自带监控/文档配置、接口清单
为什么这些文件这么常见

因为它们都服务于开发/运维的方便：git 方便回滚、备份方便恢复、phpinfo 方便排查。 方便和安全天生冲突 —— 上线时忘了关，就成了我们的入口。这也是"每个词都要问它解决了什么问题"的意义。

第 3 步：目录与接口枚举

页面只暴露了 10% 的接口。剩下的靠"猜常见名字"：

# 常见后台/调试路径
/admin  /login  /api  /debug  /test  /console  /manager  /actuator

# 用工具扫（自带字典）
# 工具箱 →「目录爆破」面板，或洪水里的 dir_brute 策略
枚举时注意"软 404"

很多站点访问不存在的路径也返回 200（带你回首页）。判断标准不是状态码，而是 响应长度/内容是否和"肯定不存在"的随机路径一致。工具里会先请求一个随机路径做基线。

第 4 步：参数与输入点

把页面里所有"能传东西"的地方列出来：URL 参数、表单字段、隐藏字段、Cookie 名、自定义头。 这一步的产出是待测清单，不是结论。

GET /search?q=x&page=1
POST /login  username, password, csrf_token
Cookie: PHPSESSID=...; role=user
Header: X-Requested-With: XMLHttpRequest
工具箱里对应什么

「洪水」首探会自动抓表单/参数/长串，并给出"专家假设"（比如"参数名像 URL → 可能是 SSRF"）； 「子域枚举」「目录爆破」「敏感文件探针」「站点爬取」「端口扫描」是五个专项面板； 策略侧有 kb_paths（flag/后台路径清单）、kb_files（泄露清单）、 api_docs、src_leak、crawl。

本章小结

步骤产出
看功能这题大概考什么
指纹什么语言/框架/版本
