第 03 章　网站是怎么跑起来的（Nginx 与后端的分工）

同一台服务器上，静态文件和动态脚本走的是两条完全不同的路。搞清楚「谁执行、执行哪个文件」，才能理解上传/包含/解析类漏洞。

本章你会得到

  • 看懂 nginx 配置里那几十行到底在说什么（root / index / location / try_files / fastcgi_pass）
  • 知道「请求一个 .php 文件」时，文件是怎么被执行的（而不是被当文本下载）
  • 搞懂三种最常见的配置级漏洞：路径解析差异、后缀判断、上传目录可执行

静态与动态：两种完全不同的处理方式

为什么必须区分

静态：请求 /a.html → 服务器把那个文件原样发给你。没有代码执行， 所以不会有 SQL 注入、命令执行。风险在"文件本身"：备份文件被下载、目录被列、软链接穿越。

动态：请求 /a.php → 服务器要启动解释器执行这个文件。 只要参数进了代码，就可能出现所有第 5~9 章的漏洞。风险在"代码怎么写"。

判断一道题属于哪类，看两件事：URL 后缀、页面有没有"根据参数变化的内容"。

一份最小 nginx 配置，逐行讲

server {
    listen 80;
    server_name shop.example.com;

    root  /var/www/html;        # 网站的"根目录"：URL 里的 / 对应这里的目录
    index index.php index.html;# 请求目录时默认找哪个文件

    location / {               # 所有路径：先找文件，找不到就交给 index.php
        try_files $uri $uri/ /index.php?$args;
    }

    location ~ \.php$ {        # 后缀是 .php 的请求：
        fastcgi_pass 127.0.0.1:9000;   # 交给 PHP-FPM 去执行
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
指令它在解决什么问题攻击者关心什么
root把 URL 映射到磁盘路径网站根在哪 → 能不能读到根外的文件
index访问目录时给个默认页目录下有没有默认页泄露
location按路径分流（静态/动态/拒绝）哪条规则先匹配？不同软件匹配顺序不同
try_files"文件不存在就换个地方找"可能把请求转给 index.php 导致奇怪的包含
fastcgi_pass把请求转给 PHP 进程上游地址一旦可控 = 直接打后端

PHP 是怎么被"执行"而不是"下载"的

关键在 SCRIPT_FILENAME：Nginx 告诉 PHP-FPM "请执行这个磁盘文件"。 PHP-FPM 收到后把文件当 PHP 代码解析，输出结果再交回 Nginx。

为什么这件事会产生漏洞

因为它依赖一个约定：「哪些请求该交给 PHP」是按路径/后缀判断的。而这个判断由 Nginx 做， 执行由 PHP 做，两边的规则不一定一致。于是出现三类经典问题：

  1. 后缀绕过：shell.php.jpg、shell.pHp、shell.php%00.jpg —— 绕过应用的上传白名单，或绕过 Nginx 的后缀匹配。
  2. 解析差异：/upload/shell.jpg/x.php 这种"路径里带 .php"的写法， Nginx 认为该交给 PHP，PHP 却去执行前面的 shell.jpg。
  3. 上传目录可执行：上传目录本来只想放图片，但配置里没有禁止执行。

三种服务器/后端组合，漏洞长相不同

组合典型坑怎么验证
Nginx + PHP-FPMfastcgi_split_path_info 配错导致任意文件当 PHP 执行 传个 1.jpg 内容写 <?php echo 7*7;?>，访问 /1.jpg/x.php
Apache + mod_php多后缀按最后一个可识别后缀执行；.htaccess 可被上传改写 传 .htaccess 把 .jpg 映射成 PHP
Tomcat / Spring路径规范化差异、;jsessionid、Actuator 暴露 访问 /actuator/env、/..;/

反向代理与"信任边界"

真实业务常是：用户 → CDN/WAF → Nginx → 应用。每一跳都会给请求加头说明"真实来源"， 比如 X-Forwarded-For、X-Real-IP。

为什么要加这些头

因为应用需要知道"用户从哪来"（限流、风控、只允许内网访问后台）。 但代理加的这个头，客户端也能自己加。如果应用只信这个头、不校验来源， 就能伪造身份 —— 这就是「IP 伪造 / 仅限本地」类题（第 10 章的信息收集也会用到）。

curl -H "X-Forwarded-For: 127.0.0.1" http://TARGET/admin
curl -H "X-Real-IP: 127.0.0.1" -H "Client-IP: 127.0.0.1" http://TARGET/admin
工具箱里对应什么

「敏感文件探针」找配置/备份；「目录爆破」找隐藏路径； 「洪水」的 host_bypass、ip_spoof、path_bypass、upload 分别对应本章的四类问题；失败时看节点详情里的原始请求，确认服务器到底怎么理解的。

本章小结

记住为什么
静态 = 发文件，动态 = 执行代码决定这道题有没有代码级漏洞
root 决定 URL 与磁盘的映射所有路径穿越/包含都相对它算
「交给谁」由 location 决定解析漏洞、后缀绕过的根源
代理加的信任头可伪造IP/来源类绕过的根源
