第 04 章　读得懂代码：PHP / Python / JS 的最小语法对照

你不需要会写项目，但要能在 30 秒内看出「这个参数流到了哪」。这一章只讲读漏洞代码要用的语法：变量、数组、函数、包含、类。

本章你会得到

  • 三份"最小语法表"：变量、数组、函数、类、文件包含，PHP/Python/JS 对照
  • 能读懂"这段代码危不危险"的五个判断点
  • 认识 PHP 的魔术方法，知道反序列化为什么能一路走到命令执行

先建立正确的期待

CTF 里的代码通常只有 20~60 行。你要做的不是"看懂每行在干什么"，而是回答五个问题：

  1. 哪个文件在处理我的请求？（入口）
  2. 它读了哪些外部输入？（$_GET / $_POST / cookie / header / 上传文件）
  3. 这些输入进了哪些危险函数？（SQL、include、eval、system、unserialize）
  4. 中间有没有过滤？过滤的是"字符"还是"语义"？
  5. 结果怎么回到我眼前？（回显 / 写文件 / 跳转 / 报错）
为什么要先学"危险函数清单"

因为它是漏洞的锚点。一段 50 行的代码，只要扫到 include($_GET[...])， 你就知道这题八成是文件包含，剩下的只是绕过。清单比语法重要得多。

eval($code);                       // ⑩ 直接执行代码
为什么 PHP 特别多这类洞

历史原因：它天生为"模板里嵌代码"设计，include 一个变量路径、eval 一段字符串都很自然；早期也没有成熟的参数化查询习惯。结果就是 危险函数离用户输入特别近。

这不代表别的语言安全。Python 的 eval/pickle、 Node 的 eval/child_process、Java 的 Runtime.exec 是同一个病，只是入口长相不同。

类与魔术方法：反序列化的钥匙

class User {
    public $name = 'guest';
    public $isAdmin = false;

    public function __wakeup() {          // 反序列化时会自动调用
        if ($this->isAdmin) {
            // 给自己发管理员权限
        }
    }
    public function __destruct() {        // 对象销毁时自动调用
        // 常用于"删临时文件""写日志"
    }
}
为什么要专门记 __wakeup / __destruct

因为反序列化漏洞的利用链（POP 链）就是靠这些自动被调用的方法串起来的： 你控制对象的属性 → 服务器还原对象 → 自动调用 __destruct → 它内部又调了别的对象的方法 → 一路走到"读文件/执行命令"。

第 9 章会用一个完整例子走一遍。现在只要记住：看到 unserialize + 可控输入 = 高危。

过滤为什么常常挡不住

过滤写法看起来在防什么为什么会被绕
str_replace('select', '', $s)去掉 select 只替换一次："selselectect" 去掉中间的又拼回来了（SELselectECT 同理）
preg_match('/union/')拦 union大小写、注释、换行、编码都能变
只查后缀 .php不让传 php.php5、.phtml、.pHp、双后缀
黑名单关键字拦危险词换个等价函数（system→passthru/反引号）
结论：过滤"字符"永远可以被绕，"过滤语义"才有效

参数化查询、白名单、禁用外部实体 —— 这些是"语义级"防御，绕不过； 而 str_replace 这类字符级过滤，只是提高了一点成本。
