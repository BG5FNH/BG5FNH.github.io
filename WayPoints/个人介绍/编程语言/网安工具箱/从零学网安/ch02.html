第 02 章　Linux 最小必要：文件、权限、进程、命令

靶场 90% 是 Linux。这一章只讲「看懂一台被黑/被打的机器」需要的部分：路径怎么走、权限怎么读、进程怎么找、日志在哪。

本章你会得到

  • 能在脑子里画出「一个网站」在服务器上的位置（代码在哪、配置在哪、日志在哪）
  • 会读 ls -l 那串权限，知道 rwx 对目录和文件是两种意思
  • 会用 12 条命令完成 90% 的现场查看
  • 知道「拿到 shell 之后第一步干什么」

为什么有 Linux，它和 Windows 的区别在哪

服务器上跑 Linux 不是因为它"更安全"，而是因为它便宜、稳定、能远程管理、几乎不花钱： 不用买授权、可以只装需要的组件、命令行就能完成所有事（带宽小、可脚本化）。

为什么这决定了你学安全的方式

因为一切皆文件：配置是文件、设备是文件、进程信息也是文件（/proc）。 所以「读文件」这件事在 Linux 上威力特别大 —— 一个任意文件读取漏洞，往往等于 "看源码 + 看配置 + 看密码 + 看日志"四件事一起拿到。

路径：一切从 / 开始

路径放什么为什么记住它
/var/www/html/网站代码（默认站点根）读源码、找 flag.php、判断上传目录
/etc/nginx/、/etc/apache2/服务器配置看 root 指到哪、哪些路径被拒绝、上游是谁
/etc/passwd用户列表（所有人可读）确认 web 进程用哪个用户跑
/etc/shadow密码哈希（只有 root 能读）提权后才看得到，说明权限边界在哪
/var/log/nginx/access.log访问日志日志投毒（把 PHP 写进 UA，再包含这个文件）
/tmp/临时目录（任何用户可写）session 文件、竞争写马、pearcmd 落点
/proc/self/当前进程的信息（虚拟文件）/proc/self/environ、/proc/self/cmdline 常被当包含目标
相对路径 vs 绝对路径（新手最常搞混）

/etc/passwd 开头有 / → 从根开始，叫绝对路径。
../../etc/passwd 没有 → 从"当前工作目录"开始往上退，叫相对路径。
漏洞里写 ../../ 能成功，前提是程序当前目录在某个深层目录里（比如 /var/www/html/upload/）。 所以同一个 payload 在这题能穿、在那题穿不动，差别就在当前目录。

权限：rwx 的三组，和"目录上的 x"

-rwxr-xr-x 1 www-data www-data 1234 Jan 1 12:00 index.php
│└┬┘└┬┘└┬┘   └───┬──┘ └───┬──┘
│ │  │  │        │        └── 属组
│ │  │  │        └─────────── 属主
│ │  │  └──────────────────── 其他人（other）
│ │  └─────────────────────── 属组（group）
│ └────────────────────────── 属主（owner）
└──────────────────────────── 类型：- 普通文件，d 目录，l 链接
位对文件对目录
r能读内容能列出里面有什么（ls）
w能改内容能在里面新建/删除文件
x能执行（当程序跑）能进入（能访问里面的文件）
为什么"上传目录可写"这件事很致命

上传目录通常给 web 用户 w（要存文件嘛）。如果同时它又在网站根下面， 并且服务器配置允许那里执行脚本，那么我们上传的文件就成了服务器上的一段可执行代码。 这就是 webshell 的物理基础（第 8 章）。

12 条够用的命令

命令它解决什么问题典型用法
pwd / cd我在哪 / 换目录cd /var/www/html
ls -la看有什么（含隐藏文件）找 .git、.env、备份
cat / less看文件内容cat /etc/passwd
grep -rn在目录里搜字符串grep -rn "flag" /var/www
find按名字/时间找文件find / -name "flag*" 2>/dev/null
ps aux看有哪些进程找 mysql / redis / 自研服务
ss -lntp看监听端口和对应进程内网里哪些服务没对外
id / whoami我是谁（哪个用户）拿到 shell 第一件事
env看环境变量有时 flag 就在环境变量里（本题库就有一类）
curl命令行发 HTTP 请求内网探测、确认回显
chmod / chown改权限/属主提权后常见动作
tail -f盯着日志看确认自己的请求有没有到
Windows 上的等价物（因为你在 Windows 学）

本教程所有"靶场"都在本机跑，所以你也可以用 Windows 命令看： dir（≈ls）、type（≈cat）、findstr /s（≈grep -r）、 netstat -ano（≈ss）、tasklist（≈ps）、set（≈env）。 两者对照着记，看到 writeup 里的 Linux 命令也不会慌。

拿到 shell 之后：第一分钟的检查清单

  1. id：我是谁？（www-data 还是 root，决定能不能直接读 /flag）
  2. pwd; ls -la：我在哪？当前目录有什么？（常常 flag 就在旁边）
  3. cat /flag 或 find / -name "flag*"：先试最直白的
  4. env：环境变量里有没有 FLAG
  5. cat /etc/passwd：机器上有哪些用户（提权线索）
  6. ss -lntp：内网还有什么服务（横向移动的入口）
工具箱里对应什么

「洪水」的 code_eval / param_rce / blind_rce 策略在拿到执行后 会自动跑这套清单（读 flag 常见路径、printenv、id）。 如果你手工拿到 shell，就按上面六条走。

本章小结

要记住的为什么
网站 = 代码目录 + 配置 + 日志 + 进程四样东西各自是一个攻击面
目录的 x = 能进入决定你能不能不读目录却直接访问里面文件
/tmp 谁都能写竞争、写马、session 都在这儿
