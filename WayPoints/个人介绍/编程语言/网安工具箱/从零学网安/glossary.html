术语总表

术语总表

按「它为了解决什么问题」排序 —— 每个词都先回答「为什么会有它」，再给定义。共 73 条。

术语为什么存在一句话定义章
IP 地址
IP address		机器需要一个唯一标识才能互相找到网络中一台主机的数字门牌号第 1 章
端口
port		一台机器要同时跑很多服务，得区分是哪个服务0~65535 的编号，用来区分同一 IP 上的不同服务第 1 章
DNS
Domain Name System		人记不住 IP，改名又不方便把域名翻译成 IP 的电话簿第 1 章
TCP
Transmission Control Protocol		IP 不保证送达，而网页内容不能缺块在 IP 之上提供可靠、有序传输的协议第 1 章
三次握手
three-way handshake		双方要确认彼此都能收发、并同步序号TCP 建立连接的三步确认第 1 章
TLS
Transport Layer Security		明文会被中间人看到、也无法确认对面是谁给 TCP 套上加密与身份校验的协议第 1 章
证书
certificate		加密还不够，要证明对面真的是这个域名由 CA 签发的、绑定域名与公钥的文件第 1 章
HTTP
HyperText Transfer Protocol		浏览器和服务器要约定一种'问与答'的格式一问一答的文本协议：请求行+头+体第 1 章
请求头
request header		请求除了'要什么'，还要说明'我是谁、能接受什么格式'放在请求行之后的 key: value 行第 1 章
状态码
status code		服务器要快速告诉客户端结果类别3 位数字：2xx 成功、3xx 跳转、4xx 客户端错、5xx 服务端错第 1 章
Cookie
cookie		HTTP 无状态，服务器需要'记住'你是谁浏览器保存、每次请求自动带上的 key=value第 1、7 章
Session
session		把身份数据放客户端不安全，想放服务器服务器保存的会话状态，客户端只拿一个 id第 7 章
JWT
JSON Web Token		多服务/多端时不想每次都查服务器存储自带签名、无状态的身份令牌（三段 base64）第 7 章
反向代理
reverse proxy		后端不该直接暴露，且要做统一入口挡在服务器前面的转发层（Nginx 常见）第 3 章
绝对路径
absolute path		从根开始才能唯一确定一个文件以 / 开头的路径第 2 章
相对路径
relative path		同一个文件在不同位置引用时写法不同相对于当前工作目录的路径第 2 章
权限位
permission bits		多用户共用一台机器，要区分谁能读/写/执行rwx 三组九位，分别对应属主/属组/其他人第 2 章
SUID
setuid		某些程序需要临时获得更高权限（如 passwd）执行时以文件属主身份运行的特殊位第 2 章
进程
process		一个程序要跑起来需要独立的内存与身份正在运行的程序实例，带自己的用户身份第 2 章
守护进程
daemon		服务要长期在后台跑，不能跟着终端退出脱离终端常驻后台的进程（nginx、php-fpm）第 2 章
日志
log		出问题要能回查'谁在什么时候做了什么'按时间追加记录的文本文件第 2、8 章
环境变量
environment variable		配置不该写死在代码里（不同环境不同值）进程启动时带上的 key=value 配置第 2 章
静态资源
static asset		图片/CSS/JS 不需要每次计算，直接发文件最快磁盘上原样返回的文件第 3 章
动态页面
dynamic page		内容要跟用户/数据库变化由程序运行时生成的页面第 3 章
网站根目录
document root		URL 需要映射到磁盘上的某个目录URL 里的 / 对应的磁盘目录第 3 章
location
location		同一个域名下不同路径要不同处理Nginx 里按路径匹配并分流的规则第 3 章
FastCGI
FastCGI		每次请求都启动一个 PHP 进程太慢Nginx 与 PHP-FPM 之间的通信协议第 3 章
PHP-FPM
PHP FastCGI Process Manager		PHP 需要一个常驻的进程池来处理请求管理 PHP 工作进程、执行脚本的服务第 3 章
中间件
middleware		通用逻辑（鉴权/日志/限流）不该在每个接口里重写请求进入业务代码前的一层处理链第 3 章
无状态
stateless		服务器不记会话才能横向扩展每个请求自带全部信息，服务端不保存上下文第 1、7 章
变量
variable		需要给一个值起名字，后面反复用指向内存中某个值的名字第 4 章
数组
array / list		一组同类数据要一起处理按顺序或按键存放多个值第 4 章
函数
function		同样的逻辑要复用，不要复制粘贴有名字、可传参、可返回的一段代码第 4 章
类 / 对象
class / object		数据和行为要绑在一起（一个'东西'）类是模板，对象是按模板造出来的实例第 4 章
魔术方法
magic method		有些动作要在特定时机自动发生（如销毁时清理）PHP 里以 __ 开头、由引擎自动调用的方法第 4、9 章
序列化
serialize		对象要存到文件/传网络，必须先变成字节把对象转成字符串/字节的过程第 9 章
反序列化
unserialize		从存储/网络恢复对象把字符串/字节还原成对象的过程第 9 章
POP 链
property-oriented programming		单个魔术方法不够，要把多个对象串起来用利用可控属性把一串方法调用接到危险函数上第 9 章
正则
regex		按模式匹配文本比逐字符判断方便描述字符串模式的小语言第 4 章
白名单 / 黑名单
allowlist / denylist		要么只允许已知安全，要么只拦已知危险允许集合 / 禁止集合两种过滤策略第 4 章
漏洞
vulnerability		系统在被'非预期使用'时会做错事代码/配置中可被利用来达成非预期行为的缺陷第 0 章
攻击面
attack surface		要评估'有多少地方能被碰'所有可被外部输入触达的接口与数据流第 0 章
输入校验
input validation		不可信输入必须先判断是否符合预期在使用前检查数据格式/范围/类型第 5 章
输出编码
output encoding		数据要显示在 HTML/JS 里时必须转义按上下文把特殊字符转成安全形式第 5 章
SQL 注入
SQL injection		拼接字符串会让用户输入变成 SQL 语法用户输入越界成 SQL 语句的一部分第 6 章
参数化查询
prepared statement		拼字符串治不了注入，需要把语法与数据分开先定 SQL 结构、再绑定值的查询方式第 6 章
盲注
blind injection		没有回显时仍想读数据把数据变成是非题（布尔）或时间差（时间盲）来猜第 6 章
联合注入
UNION injection		页面会显示查询结果，想把别的数据并进来用 UNION SELECT 把自定义行拼到结果里第 6 章
文件包含
local file inclusion		模板/插件需要动态加载文件，于是路径可配把用户可控路径交给 include/require 执行第 8 章
路径穿越
path traversal		限定目录内的读取常靠拼接实现用 ../ 跳出限定目录第 8 章
任意文件读取
arbitrary file read		程序需要读文件（配置/模板）用户可指定任意路径并读到内容第 8 章
伪协议
PHP wrapper		PHP 要支持各种数据源（文件/网络/内存）php://、data://、phar:// 等统一的流封装第 8 章
文件上传
file upload		用户要传头像/附件，文件必须落到服务器把客户端文件写到服务端磁盘的功能第 8 章
webshell
web shell		拿到执行能力后需要一个稳定的远程入口放在服务器上、通过 HTTP 执行命令的脚本第 8 章
条件竞争
race condition		多步操作不是原子的，中间状态可被利用在检查与使用之间插入操作来绕过限制第 8 章
命令注入
command injection		调系统命令时习惯拼接参数用户输入被 shell 当成命令的一部分第 9 章
SSTI
server-side template injection		模板引擎把字符串当模板渲染用户输入被当成模板代码执行第 9 章
SSRF
server-side request forgery		服务器需要替用户取远程资源让服务器去请求攻击者指定的地址第 9 章
XXE
XML external entity		XML 想复用文档片段，引入了外部实体解析 XML 时加载外部资源（读文件/发请求）第 9 章
反序列化漏洞
insecure deserialization		对象要跨请求/跨服务传递把不可信字节还原成对象，触发非预期行为第 9 章
越权
IDOR		接口按 id 取数据时忘了校验归属合法用户访问了不属于自己的资源第 7 章
认证 / 授权
authentication / authorization		先确认是谁，再确认能干什么认证=你是谁；授权=你能做什么第 7 章
哈希
hash		密码只需要比对，不需要还原单向函数：任意输入 → 固定长度摘要第 7 章
加盐
salt		相同密码不该得到相同哈希（防彩虹表）哈希前拼上一段随机值第 7 章
验证码
captcha		要区分'人'和'脚本'要求完成人类容易机器难的任务第 7 章
WAF
web application firewall		要在请求到达代码前挡掉明显的攻击按规则匹配并拦截恶意请求的网关第 5 章
信息泄露
information disclosure		开发/运维的方便文件常被留在线上本不该公开的信息（源码/备份/配置）可被访问第 10 章
指纹
fingerprint		知道对面是什么技术栈才能选对打法从响应头/报错/URL 推断软件与版本第 10 章
目录爆破
directory brute force		隐藏路径不会主动告诉你用字典逐个请求常见路径并比较响应第 10 章
判据
acceptance criterion		没有明确判据就会把'像'当成'是'判断一次尝试是否真的成功的硬标准第 11 章
假阳性
false positive		误判成功会让人放弃真正的问题把失败误认为成功第 11 章
回归测试
regression test		改一处容易弄坏另一处每次改动后重跑整套检查确认没坏第 11 章
节点树
node tree		一次解题有很多分支，需要看得见把每一步尝试记录成父子节点的结构第 11 章
