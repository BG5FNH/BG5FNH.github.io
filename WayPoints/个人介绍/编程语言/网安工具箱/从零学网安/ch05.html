第 05 章　输入从哪来：参数、头、Cookie、文件、JSON

所有 Web 漏洞都发生在「外部输入」上。这一章把输入的每个入口列清楚，并给出「输入 → 处理 → 存储 → 输出」这个万能分析模型。

本章你会得到

  • 七类外部输入的清单，以及每类对应的常见漏洞
  • 一个四段模型（输入/处理/存储/输出），能把任何一道题塞进去分析
  • 学会用「反射点」判断参数到底有没有进代码

什么叫"外部输入"

凡是客户端能决定的值，都是外部输入。它们的共同点：服务器必须假设它们可能是恶意的。

入口长什么样为什么危险典型漏洞
查询串/a?id=1&name=x最容易被拼进 SQL/文件路径SQLi、LFI、IDOR
请求体表单 / JSON / XML / 二进制结构复杂，解析器各有怪癖注入、XXE、反序列化
路径/a/b/../../c服务器要按路径找文件路径穿越、解析差异
请求头Host、X-Forwarded-For、User-Agent 很多代码默认"头是可信的"Host 投毒、IP 伪造、日志投毒
CookiePHPSESSID=…、自定义字段由客户端保管，可改会话伪造、反序列化
上传文件multipart 里的 filename + 内容落到磁盘上就成了文件webshell、竞争
服务端自己取的你给个 URL，它去请求服务器有内网权限SSRF
为什么"头"也算输入，很多人会漏

因为浏览器正常不会乱改头，但攻击者不用浏览器。curl 一行就能把头改成任何值。 代码里 $_SERVER['HTTP_HOST']、$_SERVER['HTTP_X_FORWARDED_FOR'] 全是用户可控的 —— 如果程序拿它拼密码重置链接、拼 SQL、做权限判断，就出事。

四段模型：把题塞进去

用法（每道题都做一遍，30 秒）
  1. 输入：我能控制的字符串，从哪个口进去？
  2. 处理：它被拼进了什么？（SQL / 路径 / 命令 / 模板 / 反序列化 / 头）
  3. 存储：有没有落地？（数据库 / 文件 / session / 缓存）
  4. 输出：结果怎么回来？（页面 / 报错 / 跳转 / 时间差 / 外带）

这四格里任何一格"看起来没问题"，都可以再问一次"真的吗"。 比如输出没有回显 → 走盲注/时间盲注/外带（第 6 章）。

判断"参数到底有没有进代码"：反射点

新手常犯的错：把 payload 发过去，看到页面里出现了自己的字符串，就以为"注入成功"。 其实那可能只是服务器把你输入原样显示出来（反射）。

反射 ≠ 执行

判断方法：发一个不可能被执行的怪串，比如 zzq7test：

  • 页面出现 zzq7test 原样 → 这是反射，说明"输入被显示"，但不代表进了 SQL/命令；
  • 发 '（单引号）出现 SQL 报错 → 这是真的进了 SQL；
  • 发 ../../etc/passwd 页面内容变了 → 真的进了文件路径；
  • 发 ;id 回显里出现 uid=33(www-data) → 真的进了命令。

工具里：洪水会先探一次反射（zqrefl9），参数会回显时把 payload 从响应里剔掉再比较 —— 就是为了不被自己的回显骗。（这功能是踩了真实题目之后加的，见开发文档 §206。）

编码：为什么 payload 常常要"变形"

输入在到达危险函数之前，可能被多层解码：URL 解码 → 表单解码 → 应用自己再 urldecode → 模板转义。 每一层都是一次"变形机会"，也是一次"绕过机会"。

场景写法为什么有效
过滤只看原始串%27 代替 '过滤没解码，后端解码后才成为引号
过滤只看小写SeLeCtSQL 关键字不分大小写
过滤只查一次selselectect替换掉中间那个又拼回来了
二次解码%2527第一层解码成 %27，第二层才是 '
路径过滤只查 ../....// 或 ..%2f替换后仍然拼出 ../

一个完整的"输入分析"示例

GET /show.php?file=news/1.txt HTTP/1.1
Host: demo.local

// 服务端（猜测）
$f = $_GET['file'];                 // 输入
include('./pages/' . $f);           // 处理：拼进包含路径
// 输出：被包含文件的内容

按四段模型：输入是 file；处理是"拼进 include 的路径"；没有存储；输出是文件内容。 那么可以试的方向就明确了：路径穿越（../../）、伪协议（php://filter）、 包含可控文件（日志/session/上传）。完全不需要背 payload，方向是分析出来的。

工具箱里对应什么

「洪水」首探会把页面里的表单字段、URL 参数、可疑长串都列出来； 「参数名盲试」在页面没暴露参数名时按常见名撞； 「发包工作台」用来手改头/体/方法，验证你猜的入口。
