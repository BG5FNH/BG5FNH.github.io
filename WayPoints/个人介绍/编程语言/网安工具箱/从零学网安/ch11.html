第 11 章　用妮露工具箱实战：面板、洪水、信息显示

前面十章讲的是「原理」，这一章讲「落点」：同一个概念，在工具箱里点哪里、看到什么、怎么判断它成功了。

本章你会得到

  • 工具箱的 12 类面板各自负责什么（40 个面板的地图）
  • 「洪水」一键流程：输入 → 跑 → 读节点 → 看详情 → 取 flag
  • 文件模式：pcap 解密与内存镜像取证（顺带解释"为什么答案有时不是 flag"）
  • 什么时候该放弃一键、转手工

洪水：一键流程的五个动作

  1. 选输入形式：左上角下拉（网址 / 文件 / 文本）。网址就是第 1 章那条链的起点。
  2. 贴地址或拖文件：拖进来会自动开始（省一次点击）。
  3. 看节点图：每个节点是一步尝试，颜色代表"有多可能是真线索"（红=不通，黄=有线索，绿=通了）。
  4. 点「详情」：能看这一步实际发的请求、收到的响应、改了哪些参数 —— 这是学习价值最高的地方。
  5. 看日志与 FLAG 板：命中会写「★ FLAG（已验证）」；未验证的候选会标「未验证」。
为什么它"能一键"却不"乱打"

因为它有判据：只认服务端亲口给的 flag。页面 200、回显里有可疑字符串、报错页， 都不算成功 —— 宁可报"0.45 分、最接近的是 XX"，也不假装解出来了。 这条规矩是踩了很多次坑之后定的（假阳性会让你放弃一道其实没做的题）。

四个按钮与暂停

按钮作用什么时候用
▶ 开始按当前输入跑一遍常规
⏸ 暂停在两个步骤之间停住（不会打断正在发的请求）想看清楚它刚才做了什么
⏭ 继续放行；若停在"待确认的 flag"上，等于说"这条不对"误报时
⏹ 结束收工，保留现有结果已经拿到想要的东西

文件模式：当题目给的不是网址

① pcap + keylog（HTTPS 流量分析）

题目给一个 sslkey.log 和一个 .pcap。原理是第 1 章的 TLS： 有了会话密钥，就能把加密流量还原成明文。

拖 zip 进去 → 自动解出两个成员 → 识别出 pcap + keylog
→ TLS 解密节点 → 在 HTTP 明文里找到 flag

② 内存镜像（取证题，"答案不是 flag"）

给一个 .raw/.vmem，问"采集时的计算机名 / IP / build 号"。 这类题答案是一段机器信息，不是 flag。工具箱会： 读注册表里的 ComputerName、DhcpIPAddress、CurrentBuildNumber → 拼成 ctfshow{主机名_IP_build} 候选 → 同时把全部事实列进「信息显示」。

如果拖错文件，它会直说

把 pcap 当内存镜像拖进去不会有主机名 —— 面板会写 "这不是内存镜像；取证题请拖 .raw/.vmem/.dmp"。不要对着空表猜。

③ 压缩包 / 图片 / 文档

压缩包会尝试列条目、试弱口令、看 CRC；图片走隐写；文档看宏。 这些都属于"文件类"，判据同样是"服务端/文件里真的给出了答案"。

什么时候该放弃一键，转手工

现象说明转哪个面板
所有策略都"不适用"页面没有它认识的形状发包工作台（手工构造第一个请求）
403 / 429 连续出现被 WAF 或限速挡了降低频率、换头、换编码（第 5 章）
有回显但拿不到 flag可能需要多步（登录→上传→包含）按节点详情里的请求，手工串起来
题目要"机器信息"答案不是 flag信息显示 / 取证大屏
学习用法：把它当"对照组"

自己做不出来时，让洪水跑一遍，然后点开每个节点的详情看它发了什么。 你会看到"原来这个参数要这么绕"——这比看 writeup 有效，因为请求是真实发出去的， 响应也是真实的。然后再关掉它，自己复现一遍。
