MoE

机器学习 · LLM · 八个专家，每个 token 只叫两个

下面八根柱子是八个专家（各自是一个前馈网络）。一个 token 进来，先由一个很小的门控网络给它打分，分数最高的前两名亮起来——这个 token 只经过这两个专家，其余六个一动不动。

所以 MoE 的账要分开算：参数量 = 8 份（模型容量大），每个 token 的算力 = 2 份（推理成本低）。这就是"参数涨十倍、算力只涨一点"的做法，也是 GPT-4、Mixtral 这类模型能塞下巨量参数的原因。

盯着门控分数看：它会变。同一句话里不同 token 走的专家并不一样——"的"和"量子"显然不该用同一套参数。但也要小心右边的失衡：如果少数专家总被选中，其他专家就白养了，所以要加一个负载均衡损失把它们拽平。

为什么这么做划算

参数量和算力解耦

稠密模型：参数 70B，每个 token 都要过 70B 的参数。MoE：总参数 8×，但每个 token 只过 2 个专家——显存要装下全部参数，算力只花 2/8。

专家会自己分工

没人告诉它谁管语法谁管事实，训练下来自然分化：有的专家专管标点、有的专管数字、有的专管某种语言。这是稀疏激活带来的涌现分工。

路由塌缩是真问题

门控一旦偏向某几个专家，它们会被训练得更好、于是更常被选中——正反馈把其余专家饿死。所以要加负载均衡损失，强行让每个专家的被选频率接近均匀。

工程上的麻烦

不同 token 去不同专家，GPU 之间要 all-to-all 通信把 token 送过去再收回来。通信开销 + 负载不均，是 MoE 训练比稠密模型难的主要原因。
